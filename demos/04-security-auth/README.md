# Category 04: Security & Authentication

Demonstrates dwara's authentication, authorization, and security
features using the default OSS build.

## What it covers

- **API key authentication** — `X-API-Key` header credential
- **Basic authentication** — `Authorization: Basic` credential
- **mTLS client-certificate authentication** — client cert mapped to
  a consumer by subject CN
- **HMAC request signing** — shared-secret signature verification
- **Authorization chain** — consumer > route > service > listener >
  global precedence (deny wins)
- **IP ACL** — allow/deny lists with CIDR ranges
- **Rate limiting** — per-route GCRA windows
- **WAF-lite** — SQLi / XSS / path-traversal heuristic filtering
- **mTLS forward headers** — `X-Client-Cert-*` identity forwarding

## Architecture

```
                    +-----------+
  HTTP :8080 ------>|           |
                    |  dwara    |----> echo:8080 (echo upstream)
  HTTPS :8443 ----->| gateway   |
  (mTLS)            |           |
  Admin :2019 ----->| (mTLS)    |
                    +-----------+
```

- **edge-http** (0.0.0.0:8080) — plaintext HTTP for API-key / Basic /
  HMAC / public / IP-ACL / rate-limit / WAF tests
- **edge-https** (0.0.0.0:8443) — TLS terminate with mTLS client-cert
  verification (client CA: `client-ca.crt`)
- **admin** (0.0.0.0:2019) — mTLS-only admin API

## Prerequisites

The shared infrastructure must be built first:

```sh
# Build the demo upstream images (from the repo root).
docker build -t dwara-demo/echo demos/_shared/upstreams/echo/

# Build the gateway image (from the repo root).
docker build -f Dockerfile.scratch -t dwara:demo .

# Ensure certs exist (generated by quickstart/gen-certs.sh).
ls demos/_shared/certs/server.crt demos/_shared/certs/client-ca.crt
```

## Running

```sh
# Start the gateway + echo upstream.
docker compose up -d

# Wait for the gateway to be ready, then run tests:
./test-01-api-key-auth.sh
./test-02-basic-auth.sh        # seeds Basic credential automatically
./test-04-mtls-auth.sh
./test-05-hmac-signing.sh
./test-08-authorization-chain.sh
./test-09-ip-acl.sh
./test-11-rate-limiting.sh
./test-13-waf-lite.sh
./test-16-mtls-forward-headers.sh

# Tear down.
docker compose down -v
```

## Test scripts

| Script | Feature | Expected |
|---|---|---|
| `test-01-api-key-auth.sh` | API key auth | valid key: 200; missing/invalid: 401 |
| `test-02-basic-auth.sh` | Basic auth | valid creds: 200; missing/invalid: 401 |
| `test-04-mtls-auth.sh` | mTLS client cert | valid cert: 200 |
| `test-05-hmac-signing.sh` | HMAC signing | missing signature: 401 (full signing documented in script) |
| `test-08-authorization-chain.sh` | Route-level authz | API-key consumer on mTLS route: 403; mTLS consumer: 200 |
| `test-09-ip-acl.sh` | IP ACL | localhost: 200 (allowed) |
| `test-11-rate-limiting.sh` | Rate limiting | 6th rapid request: 429 |
| `test-13-waf-lite.sh` | WAF-lite | SQLi/XSS/traversal: 403; clean: 200 |
| `test-16-mtls-forward-headers.sh` | mTLS forward headers | echo response contains `X-Client-Cert-*` |

> **Note:** `test-02-basic-auth.sh` calls `seed-basic-auth.sh` first to
> insert the Basic credential (`admin:secret123`) into the gateway's
> state DB. Basic auth credentials are store-managed in dwara (not
> config-declared); the seed script is idempotent.

## Configuration

See `dwara.yaml` for the full gateway config. Key sections:

- **Consumers** — three identities: `mobile-app` (API key + HMAC),
  `partner-mtls` (mTLS cert), `basic-user` (Basic auth)
- **Routes** — nine routes covering each auth/authz scenario
- **Policies** — `demo-rate-limit` (5 req/10s) and `demo-quota`
  (3 req/60s)
- **mTLS mapping** — subject CN `dwara-admin-client` maps to the
  `partner-mtls` consumer
- **mTLS forward headers** — prefix `X-Client-Cert` injects client
  cert identity into forwarded requests

## Certificates

Certificates are shared across all demos at `demos/_shared/certs/`:

| File | Purpose |
|---|---|
| `server.crt` / `server.key` | Gateway TLS server certificate |
| `client-ca.crt` | CA that signs client certs (for mTLS verification) |
| `client.crt` / `client.key` | Client certificate (CN: `dwara-admin-client`) |

For HTTPS/mTLS tests, scripts use:
```sh
curl --cacert ../_shared/certs/server.crt \
     --cert ../_shared/certs/client.crt \
     --key ../_shared/certs/client.key \
     https://localhost:8443/...
```
