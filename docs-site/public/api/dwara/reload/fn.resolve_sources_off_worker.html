Resolve registry plugin sources (DW-165) on the blocking pool.

The resolver’s downloader is synchronous by design (see wasm::source: resolution runs inside the synchronous DataPlane::reload_plugins, where a nested block_on would panic) — DNS via getaddrinfo and the sync TLS reads are blocking syscalls. Running it inside spawn_blocking keeps those syscalls off the async worker; the reload task awaits instead of holding the thread, and the resolver’s per-publish budget (60s across all source plugins) bounds the wait. Configs without source: plugins skip the thread hop entirely.
