Operator CLI logic (DW-022, decision 6): the pure halves of the dwara-cli subcommands, kept library-shaped so tests (and future callers) exercise exactly what the binary runs.

Exit-code contract (documented, load-bearing):

  • validate: 0 = valid config; 1 = ANY schema/parse/validation/ compile issue (all issues are printed, never fail-fast).
  • lint: 0 = no advisory warnings; 2 = warnings found; 1 = the file could not be parsed/validated at all (fix that first — linting an invalid config would report noise). The distinct 2 keeps “your config is wrong” and “your config compiles but smells” separable in scripts.

Lint rules are ADVISORY findings beyond validation (see lint_config): they flag config that compiles and routes traffic but likely does not do what the author meant.

The loadgen module holds the DW-024 macro load-generator rig (public for reuse and testing; the dwara-loadgen binary is a thin wrapper over it).
