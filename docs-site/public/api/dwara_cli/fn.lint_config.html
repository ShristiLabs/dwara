pub fn lint_config(gateway: &Gateway) -> Vec<LintWarning>
Expand description

Advisory lint rules BEYOND validation (a lint-clean config still validates; these findings are about intent, not correctness):

  • prefix-duplicate: two prefix routes with the identical pattern; the earlier-declared one wins the equal-length tie, so the later route can never match (validation does not see this — longest prefix ties are resolved silently at lookup time).
  • regex-shadowed-by-exact: an exact route whose path fully matches a regex route’s pattern; that path is always served by the exact route (lookup precedence), so the regex can never see it.
  • consumer-unused: no authorization rule at any level (allowed/ denied lists) and no JWT provider binds the consumer. Static over-approximation: a consumer can also be used purely by presenting credentials at runtime, so this is advisory, not an error.
  • policy-unused: the policy is attached to no consumer, route, service, listener, or gateway (global).
  • upstream-unreferenced: no service targets the upstream.

Listener port duplication across listeners is deliberately NOT a lint rule — validation already rejects conflicting binds.
