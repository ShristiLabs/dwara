1//! Observability substrate (DW-021, feature analysis sections 4.17 and
2//! 4.19): tracing spans per request phase, structured JSON access logs,
3//! Prometheus metrics, request IDs, and the unified error envelope.
4//!
5//! ## Tracing and spans
6//!
7//! `tracing` (MIT) is the substrate. Every request opens a root span
8//! named `request` carrying `request_id`, `method`, `path` (WITHOUT the
9//! query string — redaction: query strings carry tokens), `consumer`,
10//! `route`, and `listener` fields, plus child spans at each phase:
11//! `authn`, `authz`, `ratelimit`, `admission`, `upstream_pick` (emitted
12//! inside the upstream handle where the pick actually happens), and one
13//! `upstream_attempt` span per send. The binary installs a
14//! `tracing-subscriber` JSON formatter over STDOUT filtered by
15//! `DWARA_LOG` (RUST_LOG syntax, default `dwara=info`).
16//!
17//! ## OTLP decision
18//!
19//! The OTLP exporter (`opentelemetry` + `opentelemetry-otlp`) was
20//! evaluated and NOT added in v1: the crates are heavy (their own HTTP
21//! transport, tonic/protonic codegen) against a musl <25MB binary-size
22//! budget (DW-026) and a compute-conscious CI. The span STRUCTURE ships
23//! now and is proven by an in-process span-capture test (one trace shows
24//! all phases). Since #126 the exporter exists behind the default-off
25//! `otlp` cargo FEATURE on dwara-bin (the env var `DWARA_OTLP_ENDPOINT`
26//! is a binary-level knob and the tracing subscriber the exporter must
27//! hook lives in the bin; this module stays dependency-light by design).
28//! Default build: `DWARA_OTLP_ENDPOINT` remains RESERVED but inert;
29//! feature build: the spans defined here export over http/protobuf.
30//!
31//! ## Access logs
32//!
33//! One event at target `dwara::access` per completed request (rendered
34//! as one JSON line by the binary's subscriber): `ts` (subscriber
35//! timestamp), `request_id`, `method`, `path` (sanitized: no query),
36//! `status`, `duration_ms`, `route`, `consumer`, `upstream`,
37//! `endpoint`, `attempts`, and the `rate_limited` / `broken` / `shed`
38//! flags. `bytes_in`/`bytes_out` are deliberately omitted: the proxy
39//! path is zero-buffering by design (DW-009) and body sizes are not
40//! cheaply available for streamed bodies — recorded here as an honest
41//! omission rather than a wrong number. Sampling: `DWARA_ACCESS_LOG_
42//! SAMPLE` (0.0-1.0, default 1.0); responses with status >= 500 are
43//! ALWAYS logged regardless of sampling (documented rule).
44//!
45//! ## Metrics
46//!
47//! Prometheus text format on `/metrics`, reserved on every HTTP(S)
48//! listener exactly like `/healthz` (a configured route matching it is
49//! shadowed — same accepted v1 behavior). The `prometheus` crate (MIT,
50//! default features off: text format only, no protobuf exporter) backs
51//! the registry. Metric families:
52//!
53//! - `requests_total{route,listener,status_class}` counter
54//! - `request_duration_seconds{route}` histogram
55//! - `upstream_attempts_total{upstream,endpoint,status_class}` counter
56//! - `retries_total{upstream}` counter
57//! - `dwara_hedge_sent_total{upstream}` counter (DW-063) — speculative
58//!   hedge copies sent after the tail-latency timer fired
59//! - `dwara_mirror_sent_total{upstream}` counter (DW-062) — shadow
60//!   traffic mirror requests sent to a mirror upstream
61//! - `rate_limited_total{route}` counter
62//! - `dwara_rate_limiter_adaptive_factor{policy}` gauge (DW-089) — the
63//!   current adaptive rate-limit factor per policy (1.0 = configured
64//!   rate; < 1.0 tightens, > 1.0 relaxes; bounded [min, max])
65//! - `dwara_rate_limiter_origin_signal_total{policy,signal}` counter
66//!   (DW-089) — upstream origin signals received (`retry_after`), by
67//!   policy and signal (both config-bounded)
68//! - `dwara_rate_limiter_adaptive_tightened_total{policy}` counter
69//!   (DW-089) — adaptive factor decreases, by policy
70//! - `dwara_rate_limiter_adaptive_relaxed_total{policy}` counter
71//!   (DW-089) — adaptive factor increases, by policy
72//! - `dwara_canary_promotions_total{group}` counter (DW-091) — canary
73//!   promotions, by group (service name or AI alias)
74//! - `dwara_canary_rollbacks_total{group}` counter (DW-091) — canary
75//!   rollbacks (including severe-regression immediate rollbacks to 0)
76//! - `dwara_canary_weight{group}` gauge (DW-091) — current canary
77//!   weight, by group (the total weight stays constant)
78//! - `shed_total{priority}` counter
79//! - `dwara_policy_dry_run_total{phase,route}` counter (DW-041) —
80//!   requests a dry-run (monitor) policy would have rejected, by phase
81//!   (`route_limits`, `authz`, `rate_limit`, `load_shed`) and route
82//!   (`unrouted` for pre-404 listener/global policies); the request was
83//!   ALLOWED. Together with the `dwara::policy` warn events (phase,
84//!   would-be status, reason, route, consumer, request id) this family
85//!   IS the dry-run report — no separate endpoint.
86//! - `breaker_state{upstream}` gauge (0 closed, 1 open, 2 half-open)
87//! - `endpoint_health{upstream,endpoint}` gauge (1 available, 0 ejected)
88//! - `upstream_fail_open_picks{upstream}` gauge (scrape-time snapshot of
89//!   the balancer's monotonic fail-open counter; a gauge rather than a
90//!   counter so the hot pick path stays free of registry coupling)
91//! - `active_requests` gauge
92//! - `config_generation` gauge
93//! - `jwks_refresh_total{provider}` counter
94//! - `dwara_rate_limiter_evictions_total` gauge (scrape-time snapshot
95//!   of the rate-limit engine's monotonic eviction counter, aggregated
96//!   over every compiled rule; resets when a reload rebuilds the
97//!   engine; a gauge rather than a counter so the hot check path stays
98//!   free of registry coupling)
99//! - `dwara_rate_limiter_live_keys` gauge (live per-key cells across
100//!   every compiled rule, approximate, bounded by the sharded store
101//!   cap; aggregate and unlabeled — cardinality is never per key)
102//! - `dwara_webhook_events_total{kind,outcome}` counter (DW-044):
103//!   webhook deliveries by event kind and outcome — `delivered` (2xx
104//!   on some attempt), `failed` (retries exhausted / non-transient
105//!   answer / budget spent), `dropped` (never tried: envelope over the
106//!   byte cap, or delivery concurrency saturated). Both labels are
107//!   closed sets, so cardinality is bounded by construction.
108//! - `dwara_events_dropped_total` / `dwara_events_emitted_total`
109//!   gauges (DW-044, scrape-time snapshots of the event bus's
110//!   monotonic counters — gauges rather than counters so the emit path
111//!   stays a plain atomic with zero registry coupling, the same model
112//!   as the rate-limiter eviction gauge): events dropped at EMIT time
113//!   (full queue / no deliverer) and events handed to the queue.
114//! - `dwara_access_records_streamed_total{outcome}` counter (DW-121):
115//!   access records counted per flushed-batch delivery outcome —
116//!   `delivered` / `failed` (tried and not taken) / `dropped`
117//!   (per-record byte cap) — a closed three-value label set, counted
118//!   by the stream flusher, never the request path.
119//! - `dwara_access_records_offered_total` /
120//!   `dwara_access_records_dropped_total` gauges (DW-121, scrape-time
121//!   snapshots of the record stream's monotonic counters, the same
122//!   gauge-not-counter model as the event bus): records offered at
123//!   request completion and records dropped at OFFER time (channel
124//!   full / stream disabled).
125//! - `dwara_quota_denied_total{consumer,budget}` counter (DW-033) —
126//!   requests refused by a consumer request budget (429), by consumer
127//!   (the quota-configured set, config-bounded) and binding budget
128//!   (`daily`/`monthly`, a closed set). Distinct from
129//!   `rate_limited_total`: budgets are not rates.
130//! - `dwara_quota_used{consumer,budget}` / `dwara_quota_limit{consumer,
131//!   budget}` gauges (DW-033, scrape-time snapshots of the state
132//!   store's quota counters and the config caps — the same snapshot
133//!   gauge model as the rate-limiter live-keys gauge).
134//! - `dwara_admission_queued_total{outcome}` counter (DW-053) —
135//!   admission queue outcomes by closed set `admitted` (a permit was
136//!   acquired after queueing), `timeout` (the queue timeout expired;
137//!   shed with 503), `queue_full` (the queue was at capacity; shed
138//!   immediately with 503).
139//! - `dwara_admission_queue_depth` gauge (DW-053) — current number of
140//!   requests waiting in the admission queue for a concurrency permit.
141//! - `dwara_license_status` gauge (DW-032) — 0 = no license (OSS mode),
142//!   1 = valid, 2 = expired within grace period, 3 = expired past grace
143//!   period (degraded to OSS). Set at startup and on reload; no labels.
144//! - `dwara_dns_discovery_endpoints{upstream}` gauge (DW-042) — current
145//!   resolved endpoint count for DNS-discovered upstreams. The `upstream`
146//!   label is config-bounded; cardinality is never per resolved address.
147//! - `dwara_dns_discovery_refresh_total{upstream}` counter (DW-042) — DNS
148//!   discovery refresh attempts, by upstream (config-bounded label).
149//! - `dwara_dns_discovery_refresh_failures_total{upstream}` counter
150//!   (DW-042) — DNS discovery refresh failures, by upstream.
151//! - `dwara_mcp_sessions_total{state}` counter (DW-087) — MCP session
152//!   lifecycle transitions, by state (`initialized`, `closed`,
153//!   `expired`). A closed three-value label set, so cardinality is
154//!   three series total.
155//! - `dwara_mcp_tool_calls_total{tool,status}` counter (DW-087) — MCP
156//!   tool calls, by tool (config-bounded) and status (`success`,
157//!   `error`, `denied`). No consumer label (cardinality rule).
158//! - `dwara_mcp_tool_duration_seconds{tool}` histogram (DW-087) — MCP
159//!   tool call duration (authz check through upstream response), by
160//!   tool (config-bounded label).
161//! - `dwara_a2a_requests_total{agent,outcome}` counter (DW-114) — A2A
162//!   (agent-to-agent) requests, by agent (config-bounded) and outcome
163//!   (`success`, `error`, `stubbed`). No consumer label (cardinality
164//!   rule).
165//! - `dwara_a2a_sessions_total{state}` counter (DW-114) — A2A session
166//!   lifecycle transitions, by state (`initialized`, `closed`,
167//!   `expired`). A closed three-value label set (mirrors MCP), so
168//!   cardinality is three series total.
169//! - `dwara_tls_pq_handshakes_total{result}` counter (DW-105) —
170//!   post-quantum TLS handshake outcomes, by result (`success`,
171//!   `fallback`, `disabled`). A closed three-value label set, so
172//!   cardinality is three series total.
173//! - `dwara_graphql_requests_total{route,outcome}` counter (DW-099) —
174//!   GraphQL check outcomes, by route (config-bounded) and outcome
175//!   (`allowed`, `depth_exceeded`, `complexity_exceeded`,
176//!   `persisted_query_required` — a closed four-value set).
177//! - `dwara_graphql_depth{route}` gauge (DW-099) — last query depth for
178//!   a GraphQL-configured route (config-bounded label).
179//! - `dwara_nano_service_requests_total{route,outcome}` counter (DW-106)
180//!   — nano-service (WASM route handler) request outcomes, by route
181//!   (config-bounded) and outcome (`success`, `error`, `timeout` — a
182//!   closed three-value set). No consumer label (cardinality rule).
183//! - `dwara_nano_service_duration_seconds{route}` histogram (DW-106) —
184//!   nano-service `handle` call duration, by route (config-bounded
185//!   label).
186//! - `dwara_plugin_failures_total{name,reason}` counter (DW-157) —
187//!   plugin dispatch failures, by plugin name (config-bounded) and
188//!   reason (`crashed`, `disabled`, `not_loaded`, `not_registered`,
189//!   `instantiate_failed`, `trap`, `body_too_large`,
190//!   `response_stream_ended` — a closed set).
191//!   One increment per request the plugin chain answered with an error
192//!   (a plugin short-circuit via `send_http_response` is a plugin
193//!   DECISION, not a failure, and is not counted; the access-log
194//!   `plugin_short_circuit` flag marks those).
195//! - `dwara_plugin_total{state}` gauge (DW-158) — plugins loaded per
196//!   lifecycle state (`healthy`, `crashed`, `disabled`, `not_loaded`,
197//!   `not_registered` — a closed five-value set over the generation's
198//!   declared plugins, the same enumeration `GET /plugins` serves).
199//!   Refreshed at publish time (every config generation); state changes
200//!   that happen between publishes (a crash counted at request time)
201//!   land on the next publish or are visible per-request in
202//!   `dwara_plugin_failures_total`.
203//! - `dwara_graphql_complexity{route}` gauge (DW-099) — last query
204//!   complexity for a GraphQL-configured route (config-bounded label).
205//! - `dwara_l4_connections_total{listener,protocol}` counter (DW-103) —
206//!   L4 connections proxied, by listener (config-bounded) and protocol
207//!   (`tcp`, `udp` — a closed two-value set). Counted once per accepted
208//!   L4 connection (before the splice is established).
209//! - `dwara_l4_connection_duration_seconds{listener}` histogram
210//!   (DW-103) — L4 connection duration (splice establishment through
211//!   close), by listener (config-bounded label).
212//! - `dwara_ai_request_duration_seconds{provider,route}` histogram
213//!   (AI-07) — AI request latency (request parse through response
214//!   translation), by provider and route (both config-bounded). Observed
215//!   once per completed AI request (success and provider/translation
216//!   errors alike; client-side rejections never reach a provider).
217//! - `dwara_ai_tokens_per_request{provider,model,kind}` histogram
218//!   (AI-07) — distribution of provider-reported tokens per request, by
219//!   provider (config-bounded), provider_model (config-bounded), and
220//!   kind (the closed set `prompt` | `completion`). Provider-reported
221//!   only; the gateway never estimates. No consumer label (cardinality).
222//!
223//! ## OTel GenAI semantic conventions (AI-07)
224//!
225//! AI request spans carry the OpenTelemetry GenAI semantic-convention
226//! `gen_ai.*` attributes (<https://opentelemetry.io/docs/specs/semconv/gen-ai/>):
227//! `gen_ai.system` (the provider kind), `gen_ai.request.model`
228//! (the client alias), `gen_ai.response.model` (the provider model that
229//! served), `gen_ai.request.{max_tokens,temperature,top_p}`, and the
230//! provider-reported `gen_ai.usage.{prompt_tokens,completion_tokens,
231//! total_tokens}`, `gen_ai.response.finish_reasons`, and
232//! `gen_ai.response.id`. The helpers [`record_gen_ai_request_attrs`] and
233//! [`record_gen_ai_response_attrs`] record them onto a span created with
234//! every `gen_ai.*` field declared `Empty` (the span lives in
235//! `dataplane::ai_proxy::serve_ai`).
236//!
237//! ## Error envelope (section 4.19)
238//!
239//! Every gateway-generated non-success body — including the reserved
240//! `/healthz`/`/readyz` responses, which are aligned to the same shape —
241//! is `{"error":{"code","message","request_id"}}`. Messages never leak
242//! upstream internals: classification strings only ("upstream
243//! unavailable", not hyper error text).
244//!
245//! ## Request IDs
246//!
247//! An inbound `X-Request-Id` is respected when it is printable ASCII of
248//! at most 128 bytes (anything else is replaced — a hostile ID must not
249//! smuggle control bytes into logs); otherwise a process-unique ID is
250//! generated (wall-clock nanoseconds + per-process counter — cheaper
251//! than a UUID, no extra dependency). The ID is echoed on the response
252//! as `X-Request-Id` and available to every span and log line.
253//!
254//! ## Redaction rules (hard requirements)
255//!
256//! - Paths are logged WITHOUT query strings.
257//! - No Authorization / Proxy-Authorization / Cookie / Set-Cookie /
258//!   X-API-Key VALUES are ever emitted by this module or the tracing
259//!   calls it fronts; field lists below are exhaustive.
260//! - JWKS bodies, credentials, and keys are never logged.

328    }

409/// Emit one access-log event (one JSON line under the binary's
410/// subscriber). The field list is exhaustive and redacted by
411/// construction: no headers, no query string, no credentials.
412/// `bytes_in`/`bytes_out` (PERF-12, #209): `bytes_in` is the declared
413/// `Content-Length` (0 for chunked); `bytes_out` is the frame-counted
414/// response body size (read from the atomic the `CountingBody`
415/// wrapper updated as frames streamed to the client).
416pub fn emit_access(rec: &AccessRecord) {
417    let bytes_out = rec.bytes_out.load(std::sync::atomic::Ordering::Relaxed);
418    tracing::info!(
419        target: "dwara::access",
420        request_id = %rec.request_id,
421        method = %rec.method,
422        path = %rec.path,
423        status = rec.status,
424        duration_ms = rec.duration_ms,
425        route = %rec.route,
426        consumer = %rec.consumer,
427        upstream = rec.upstream.as_deref().unwrap_or(""),
428        endpoint = rec.endpoint.as_deref().unwrap_or(""),
429        attempts = rec.attempts,
430        rate_limited = rec.rate_limited,
431        broken = rec.broken,
432        shed = rec.shed,
433        plugin_short_circuit = rec.plugin_short_circuit,
434        bytes_in = rec.bytes_in,
435        bytes_out = bytes_out,
436        "access"
437    );
438}

440/// The unified error body (section 4.19): a JSON object an operator can
441/// grep and a client can correlate. `code` is a stable machine token,
442/// `message` a human string with no upstream internals, `request_id`
443/// ties the response to the trace/access log.
444pub fn envelope_body(code: &str, message: &str, request_id: &str) -> bytes::Bytes {
445    // Manual JSON formatting avoids the serde_json::Value intermediate
446    // allocation (the json! macro builds a Value tree, then to_string()
447    // serializes it back — two heap allocations). The envelope shape is
448    // fixed; we pre-allocate one String and JSON-escape each field.
449    fn escape_into(out: &mut String, s: &str) {
450        for c in s.chars() {
451            match c {
452                '"' => out.push_str("\\\""),
453                '\\' => out.push_str("\\\\"),
454                '\n' => out.push_str("\\n"),
455                '\r' => out.push_str("\\r"),
456                '\t' => out.push_str("\\t"),
457                c if c < ' ' => out.push_str(&format!("\\u{:04x}", c as u32)),
458                c => out.push(c),
459            }
460        }
461    }
462    let mut buf = String::with_capacity(64 + code.len() + message.len() + request_id.len());
463    buf.push_str(r#"{"error":{"code":""#);
464    escape_into(&mut buf, code);
465    buf.push_str(r#"","message":""#);
466    escape_into(&mut buf, message);
467    buf.push_str(r#"","request_id":""#);
468    escape_into(&mut buf, request_id);
469    buf.push_str(r#""}}"#);
470    bytes::Bytes::from(buf)
471}

473/// Validate an inbound `X-Request-Id` value: printable ASCII (0x20-0x7E),
474/// at most 128 bytes. Anything else (control bytes, UTF-8 multibyte,
475/// overlong) is rejected so hostile IDs cannot smuggle control
476/// characters into logs.
477pub fn valid_inbound_request_id(v: &[u8]) -> bool {
478    !v.is_empty() && v.len() <= 128 && v.iter().all(|b| (0x20..=0x7e).contains(b))
479}
480
481/// Resolve the request's correlation ID: a valid inbound `X-Request-Id`
482/// verbatim, else a generated one (`req-` + hex wall-clock nanoseconds +
483/// hex process counter; unique per process, no dependency pulled in for
484/// randomness — request IDs are correlation handles, not secrets).
485pub fn resolve_request_id(headers: &HeaderMap) -> String {
486    if let Some(v) = headers.get(&X_REQUEST_ID) {
487        if valid_inbound_request_id(v.as_bytes()) {
488            if let Ok(s) = v.to_str() {
489                return s.to_string();
490            }
491        }
492    }
493    generate_request_id()
494}
495
496/// Per-process request-ID counter (the low bits of the wall clock are
497/// already unique per nanosecond; the counter disambiguates coarse
498/// clocks and multi-ID calls within one nanosecond).
499static REQUEST_COUNTER: AtomicU64 = AtomicU64::new(0);
500
501/// Public for testing the request-id generation contract.
502pub fn generate_request_id() -> String {
503    let n = std::time::SystemTime::now()
504        .duration_since(std::time::UNIX_EPOCH)
505        .map(|d| d.as_nanos())
506        .unwrap_or(0);
507    let c = REQUEST_COUNTER.fetch_add(1, Ordering::Relaxed);
508    format!("req-{:016x}-{:06x}", n, c & 0xff_ffff)
509}

511/// Cheap sampling PRNG: a Weyl-sequence over one atomic (add a large
512/// odd constant, use the high bits of the product). Not cryptographic —
513/// it only decides whether an access-log line is emitted.
514struct SampleRng {
515    state: AtomicU64,
516}
517
518impl SampleRng {
519    fn new() -> Self {
520        let seed = std::time::SystemTime::now()
521            .duration_since(std::time::UNIX_EPOCH)
522            .map(|d| d.as_nanos() as u64)
523            .unwrap_or(0x9e37_79b9_7f4a_7c15);
524        SampleRng {
525            state: AtomicU64::new(seed | 1),
526        }
527    }
528
529    fn next_f64(&self) -> f64 {
530        let x = self
531            .state
532            .fetch_add(0x9e37_79b9_7f4a_7c15, Ordering::Relaxed);
533        // Multiply-shift normalization into [0, 1).
534        ((x.wrapping_mul(0x9e37_79b9_7f4a_7c15)) >> 11) as f64 / (1u64 << 53) as f64
535    }
536}

3127//
3128// Per-route objectives (config: routes[].slo) exported as burn-rate
3129// metrics for multiwindow alerting. Availability counts a request BAD
3130// when the gateway answered 5xx (client errors are the caller's
3131// policy, not availability); latency counts a request BAD when the
3132// end-to-end duration exceeds the configured threshold. Burn rate is
3133// the standard error-budget consumption signal:
3134//
3135//   burn = (bad_fraction over window) / (1 - target)
3136//
3137// 1.0 = consuming budget at exactly the allowed rate (the budget lasts
3138// its whole period); 14.4 over 1h = the 28-day budget exhausted in
3139// ~49 hours (the classic fast-burn page); 6 over 1h the slow-burn
3140// signal. The exported windows are the alerting pair 5m and 1h.
3141//
3142// Values are computed from in-process sliding-window counters (15 s
3143// buckets) and published at SCRAPE time through a custom Collector —
3144// always fresh, never a stale sampled gauge, and no background task.
3145// The windows are process-local: they start empty at boot (documented
3146// — burn rates become meaningful as traffic accumulates, and a restart
3147// is itself an availability event the SLOs of OTHER processes catch).
3148
3149/// Plain per-route SLO targets. Primitives on purpose: observability
3150/// depends on nothing, so the config types are converted at the call
3151/// site (dataplane refresh).
3152#[derive(Debug, Clone, Copy, PartialEq)]
3153pub struct SloTargets {
3154    /// Availability target as a fraction in (0, 1]: the share of
3155    /// requests that must NOT be a gateway-answered 5xx.
3156    pub availability: f64,
3157    /// Latency objective threshold in milliseconds. `None` = no
3158    /// latency objective for this route.
3159    pub latency_threshold_ms: Option<f64>,
3160    /// Latency target as a fraction in (0, 1): the share of requests
3161    /// that must complete within `latency_threshold_ms`.
3162    pub latency_target: f64,
3163}
3164
3165/// Sliding-window bucket width (15 s): the 5m window is 20 buckets,
3166/// the 1h window 240 — per route, trivially small, and granular
3167/// enough that scrape-time computation is never more than one bucket
3168/// stale.
3169const SLO_BUCKET_MS: i64 = 15_000;
3170
3171/// The exported windows: (milliseconds, label). The standard
3172/// multiwindow-burn-rate alerting pair.
3173const SLO_WINDOWS: [(i64, &str); 2] = [(300_000, "5m"), (3_600_000, "1h")];
3174
3175#[derive(Debug, Default, Clone, Copy)]
3176struct SloBucket {
3177    start_ms: i64,
3178    total: u64,
3179    errors: u64,
3180    over_latency: u64,
3181}
3182
3183#[derive(Debug)]
3184struct SloRouteState {
3185    targets: SloTargets,
3186    /// One ring per [`SLO_WINDOWS`] entry; the ring at index i has
3187    /// `SLO_WINDOWS[i].0 / SLO_BUCKET_MS` buckets.
3188    rings: Vec<Vec<SloBucket>>,
3189}
3190
3191impl SloRouteState {
3192    fn new(targets: SloTargets) -> Self {
3193        let rings = SLO_WINDOWS
3194            .iter()
3195            .map(|(ms, _)| {
3196                let n = (*ms / SLO_BUCKET_MS) as usize;
3197                vec![SloBucket::default(); n.max(1)]
3198            })
3199            .collect();
3200        SloRouteState { targets, rings }
3201    }
3202
3203    /// Record one outcome into every ring (each ring buckets
3204    /// independently by its own wraparound index).
3205    fn record(&mut self, now_ms: i64, error: bool, over_latency: bool) {
3206        let idx = (now_ms / SLO_BUCKET_MS) as usize;
3207        let stamp = idx as i64 * SLO_BUCKET_MS;
3208        for ring in &mut self.rings {
3209            let slot = idx % ring.len();
3210            let b = &mut ring[slot];
3211            if b.start_ms != stamp {
3212                *b = SloBucket {
3213                    start_ms: stamp,
3214                    ..SloBucket::default()
3215                };
3216            }
3217            b.total += 1;
3218            if error {
3219                b.errors += 1;
3220            }
3221            if over_latency {
3222                b.over_latency += 1;
3223            }
3224        }
3225    }
3226
3227    /// Sum a window ring over the buckets whose start is within the
3228    /// window ending at `now_ms` (whole buckets; a partially-expired
3229    /// edge bucket is included — the 15 s granularity is the
3230    /// documented precision).
3231    fn sums(&self, ring: usize, now_ms: i64) -> (u64, u64, u64) {
3232        let cutoff = now_ms - SLO_WINDOWS[ring].0;
3233        let mut total = 0u64;
3234        let mut errors = 0u64;
3235        let mut over = 0u64;
3236        for b in &self.rings[ring] {
3237            if b.start_ms > cutoff && b.total > 0 {
3238                total += b.total;
3239                errors += b.errors;
3240                over += b.over_latency;
3241            }
3242        }
3243        (total, errors, over)
3244    }
3245}

3247/// The SLO collector: owns the per-route window state and the two
3248/// output families, refreshing the gauges from the windows when
3249/// Prometheus gathers (scrape time — see the section docs).
3250struct SloState {
3251    routes: std::sync::RwLock<std::collections::HashMap<String, SloRouteState>>,
3252    /// PERF: `record` runs on EVERY completed request, but most fleets
3253    /// configure no route SLOs — the empty-map case still paid a
3254    /// `RwLock::write` (exclusive across every worker thread) per
3255    /// request. This flag gates that lock away entirely; it is
3256    /// maintained under the same write guard as the map swap, so
3257    /// `false` implies the map is empty and `record`'s `get_mut` would
3258    /// have missed anyway. A record racing a generation swap can slip
3259    /// one sample into the outgoing map or skip one in the incoming
3260    /// map — the same tolerance the pre-existing swap race already
3261    /// had, and far below one window's noise floor.
3262    configured: std::sync::atomic::AtomicBool,
3263    burn_rate: prometheus::GaugeVec,
3264    target: prometheus::GaugeVec,
3265}

3274                 1.0 consumes the budget at exactly the allowed rate; \
3275                 14.4 over 1h is the classic fast-burn page. window: 5m or \
3276                 1h (process-local sliding windows — they start empty at \

3301    /// Swap the configured route set (dataplane refresh). Routes that
3302    /// vanish from the config lose their gauge children so a removed
3303    /// SLO stops exporting stale series.
3304    fn set_routes(&self, slos: Vec<(String, SloTargets)>) {
3305        let mut routes = self.routes.write().expect("slo state lock");
3306        let names: std::collections::HashSet<String> =
3307            slos.iter().map(|(n, _)| n.clone()).collect();
3308        for gone in routes.keys().filter(|n| !names.contains(*n)) {
3309            let name = gone.as_str();
3310            let objectives: &[&str] = if routes[gone].targets.latency_threshold_ms.is_some() {
3311                &["availability", "latency"]
3312            } else {
3313                &["availability"]
3314            };
3315            for objective in objectives {
3316                for window in ["5m", "1h"] {
3317                    let _ = self
3318                        .burn_rate
3319                        .remove_label_values(&[name, objective, window]);
3320                }
3321                let _ = self.target.remove_label_values(&[name, objective]);
3322            }
3323        }
3324        routes.clear();
3325        for (name, targets) in slos {
3326            routes.insert(name, SloRouteState::new(targets));
3327        }
3328        // Maintained under the write guard so a `record` in flight sees
3329        // either the fully swapped map with the flag set, or the gate
3330        // closed and no lock at all (see the field docs).
3331        self.configured
3332            .store(!routes.is_empty(), std::sync::atomic::Ordering::Release);
3333    }

3335    /// Record one completed request's outcome for a configured route
3336    /// (no-op for routes without an SLO — the common case).
3337    fn record(&self, route: &str, status: u16, duration_ms: f64, now_ms: i64) {
3338        if !self.configured.load(std::sync::atomic::Ordering::Acquire) {
3339            return;
3340        }
3341        if let Some(state) = self.routes.write().expect("slo state lock").get_mut(route) {
3342            let error = status >= 500;
3343            let over_latency = state
3344                .targets
3345                .latency_threshold_ms
3346                .is_some_and(|t| duration_ms > t);
3347            state.record(now_ms, error, over_latency);
3348        }
3349    }

3351    /// Refresh the gauge children from the current windows (scrape
3352    /// time). No traffic in a window => burn 0.0 (no consumption), by
3353    /// explicit decision: NaN would break alerting comparisons.
3354    fn refresh(&self, now_ms: i64) {
3355        let routes = self.routes.read().expect("slo state lock");
3356        for (route_name, state) in routes.iter() {
3357            let name = route_name.as_str();
3358            let allowed_avail = 1.0 - state.targets.availability;
3359            for (ring, (_, window)) in SLO_WINDOWS.iter().enumerate() {
3360                let (total, errors, over) = state.sums(ring, now_ms);
3361                let burn = if total > 0 && allowed_avail > 0.0 {
3362                    (errors as f64 / total as f64) / allowed_avail
3363                } else {
3364                    0.0
3365                };
3366                self.burn_rate
3367                    .with_label_values(&[name, "availability", window])
3368                    .set(burn);
3369                if state.targets.latency_threshold_ms.is_some() {
3370                    let allowed_lat = 1.0 - state.targets.latency_target;
3371                    let burn = if total > 0 && allowed_lat > 0.0 {
3372                        (over as f64 / total as f64) / allowed_lat
3373                    } else {
3374                        0.0
3375                    };
3376                    self.burn_rate
3377                        .with_label_values(&[name, "latency", window])
3378                        .set(burn);
3379                }
3380            }
3381            self.target
3382                .with_label_values(&[name, "availability"])
3383                .set(state.targets.availability);
3384            if state.targets.latency_threshold_ms.is_some() {
3385                self.target
3386                    .with_label_values(&[name, "latency"])
3387                    .set(state.targets.latency_target);
3388            }
3389        }
3390    }
3391}

3400    fn collect(&self) -> Vec<prometheus::proto::MetricFamily> {
3401        let now = unix_now_ms();
3402        self.refresh(now);
3403        let mut families = self.burn_rate.collect();
3404        families.extend(self.target.collect());
3405        // A family with zero children (no route has an SLO — the
3406        // default) would make the text encoder PANIC on "no metrics";
3407        // emit nothing instead (an unconfigured feature exports no
3408        // series, exactly like a family that was never registered).
3409        families.retain(|f| !f.get_metric().is_empty());
3410        families
3411    }
